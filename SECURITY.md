# Security Policy

Do not open public issues for suspected vulnerabilities. Report privately to the security contact configured for the project, including affected version, impact, reproduction, indicators of active exploitation and safe contact details. The project will acknowledge, triage, preserve evidence, coordinate remediation and credit, and publish an advisory when safe.

Only supported release lines receive fixes. Release artifacts must be verified against published signatures and provenance. If a signing key, plugin or update channel is suspected compromised, stop deployment, preserve relevant logs/artifacts and invoke the key/package revocation runbook.
